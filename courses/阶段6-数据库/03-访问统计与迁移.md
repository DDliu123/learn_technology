## 1. 为什么要单独建 Visit 表，而不是加个 clicks 字段

| 方案 | 能回答的问题 |
|---|---|
| 在 short_link 上加 `clicks: int` | 只有「总共点了几次」 |
| 单独的 visit 表（每次访问一行） | 总数、**什么时候点的**、趋势、来源设备、去重统计 |

「一次访问 = 一行日志」保留全部细节；只有一个总数，历史就永久丢了。
**日志型数据一律单独建表**，这是建模的默认选择。

```python
class Visit(SQLModel, table=True):
    __tablename__ = "visit"
    id: Optional[int] = Field(default=None, primary_key=True)
    code: str = Field(index=True)              # 索引：统计查询都按 code 过滤，没索引大表会慢
    visited_at: str = Field(default_factory=lambda: datetime.now(timezone.utc).isoformat())
    user_agent: Optional[str] = None           # 浏览器标识，以后可做来源分析
```

## 2. 跳转时记一次，然后统计

```python
# app.py 的 redirect 里
record_visit(code, user_agent=request.headers.get("user-agent"))
return RedirectResponse(url=link.url, status_code=307)
```

**统计和跳转不放在同一个事务**：就算统计写失败，也不该挡住用户跳转。
取舍原则：统计宁可少记一条，也不能让短链失效。

```python
def get_stats(code: str, recent_limit: int = 5) -> LinkStats | None:
    with Session(engine) as session:
        link = _find_by_code(session, code)
        if link is None:
            return None
        # 聚合：SELECT count(id) FROM visit WHERE code = ?
        clicks = session.exec(select(func.count(Visit.id)).where(Visit.code == code)).one()
        recent = session.exec(
            select(Visit.visited_at).where(Visit.code == code)
            .order_by(Visit.visited_at.desc()).limit(recent_limit)
        ).all()
        return LinkStats(code=link.code, url=link.url, clicks=clicks,
                         created_at=link.created_at, recent_visits=list(recent))
```

**用数据库 COUNT，不要取出来数**：`func.count` 在数据库里算完只返回一个数字；
`len(session.exec(...).all())` 会把全部行搬到 Python 里再数 —— 10 万条时差距是数量级的。

路由用 `/stats/{code}` 而不是 `/{code}/stats`：离通配路由 `/{code}` 远一点，Swagger 里也更清楚。

## 3. 迁移（migration）是什么，为什么现在还不需要 Alembic

`create_db_and_tables()` 实际做的是 `SQLModel.metadata.create_all(engine)`：

| 场景 | create_all 行为 |
|---|---|
| 表不存在 | **会建**（本课新增 visit 表，重启就自动建出来了 ✅） |
| 表已存在 | 跳过，不动 |
| 表结构要改（加/删字段） | **不会改** ❌ |

所以给 `ShortLink` 加一个新字段后，老库里的 `short_link` 表不会多出那一列，
代码一读就报「no such column」。

| 阶段 | 做法 |
|---|---|
| 现在（开发期、数据可丢） | 直接删掉 `shortlink.db` 重跑，让 create_all 重建 |
| 生产（数据不能丢） | 用 **Alembic** 写迁移脚本：记录「从 A 版本结构变到 B 版本」的升级/回滚步骤，随代码版本一起管理 |

一句话：**create_all 管建表，Alembic 管改表**。生产里结构变更必须走迁移，不能直接删库。

## 5. 本机踩坑

| 现象 | 解法 |
|---|---|
| 断言 `url == "https://x.com"` 失败，实际是 `"https://x.com/"` | `AnyHttpUrl` 会自动规范化加尾斜杠（阶段 5 讲过），断言按规范化后的值写 |
| 加了新表但没建出来 | `create_all` 只在启动时跑；重启服务才会建新表 |
| 改了模型字段，老表没变 | create_all 不改结构；开发期删 `shortlink.db` 重建，生产用 Alembic |
