## 1. 重定向：用 RedirectResponse，别返回元组

想让浏览器真正跳走，必须返回 `RedirectResponse`，不是 `(307, {...})` 元组（那只是给响应体设了状态码，不会跳转）：

```python
from fastapi.responses import RedirectResponse

@app.get("/{code}")
def redirect(code: str):
    link = get_link(code)
    if link is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="短码不存在")
    return RedirectResponse(url=link.url, status_code=status.HTTP_307_TEMPORARY_REDIRECT)
```

| 点 | 说明 |
|---|---|
| `RedirectResponse(url=..., status_code=307)` | 真正发 `Location` 头让浏览器跳转 |
| 307 | 临时重定向，保留原请求方法（301/308 是永久，客户端会缓存，调试期别用） |
| 放在固定路由之后 | `/links`、`/shorten` 先定义；FastAPI 按定义顺序匹配，固定路径优先于 `{code}` 通配，避免把 `"links"` 当 code 误匹配 |

## 2. 删除：204 无内容

```python
@app.delete("/{code}", status_code=status.HTTP_204_NO_CONTENT)
def remove(code: str):
    if not delete_link(code):
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="短码不存在")
```

204 = 删除成功但**响应没有 body**。这条路由成功时不返回任何 JSON，只在 HTTP 头里带 204。

---

## 3. 错误处理统一姿势：路由只抛 HTTPException

所有「找不到 / 冲突 / 没权限」都统一用 `HTTPException(status_code, detail=...)`：
- 函数本身只写正常逻辑；
- 异常分支用 `raise HTTPException`，FastAPI 自动序列化成 `{"detail": "..."}` 返回对应状态码。

**阶段 5 完整状态码清单**：

| 码 | 含义 | 触发点 |
|---|---|---|
| 200 | 成功返回 | GET /、/health、/links |
| 201 | 已创建 | POST /shorten 成功 |
| 204 | 删除成功（无 body） | DELETE /{code} 成功 |
| 307 | 临时重定向 | GET /{code} 命中 |
| 404 | 资源不存在 | GET/DELETE /{code} 未命中 |
| 409 | 冲突 | POST /shorten 自定义短码重复 |
| 422 | 请求体校验失败 | Pydantic 校验不过（url / code） |

## 4. 无浏览器自动化测试：TestClient

起真服务、开浏览器点太慢。FastAPI 自带 `TestClient`，在内存里直接打路由，断言响应：

```python
from fastapi.testclient import TestClient
from shortlink_api.app import app

def main():
    with TestClient(app) as client:
        r = client.post("/shorten", json={"url": "https://example.com/a"})
        assert r.status_code == 201
        code = r.json()["code"]
        r = client.get(f"/{code}", follow_redirects=False)
        assert r.status_code == 307
        assert r.headers["location"] == "https://example.com/a"
        ...
```

| 点 | 说明 |
|---|---|
| `TestClient(app)` | 复用同一个 app，不需要真端口 |
| `follow_redirects=False` | 默认不跟随，才能断言到「307 本身」和 `Location` 头；要测真跳转再开 `True` |
| `headers["location"]` | 重定向目标在响应头里，不在 body |
| 跑法 | `uv run python tests/test_api.py`（纯脚本，不引 pytest 也能跑） |

本课 9 条断言全绿：`tests/test_api.py` → `ALL TESTS PASSED ✅`

> 注：终端会打印一条 `StarletteDeprecationWarning: ... install httpx2` 的警告，不影响测试通过，是库版本演进提示，阶段内忽略。

## 5. 本机踩坑（本课重点）

| 现象 | 解法 |
|---|---|
| 加了 `GET /{code}` 路由，curl 还是 404 | `fastapi dev` 热重载对「新增路由 + 改 import」经常不灵；**杀进程干净重启**再测（本课两次实测都踩到） |
| 返回 `(307, {"location":...})` 浏览器不跳 | 那是给 body 设状态码，必须用 `RedirectResponse` |
| DELETE 后想看返回内容，一片空白 | 204 本就该无 body，看状态码即可 |
| curl 测重定向看到 307 就停 | 目标域名若是示例域名解析不了，curl 自然停；断言 `Location` 头即可证明跳转逻辑对 |
