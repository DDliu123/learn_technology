# 阶段 7 · 第 1 课：用户模型与密码哈希（绝不存明文）

> 项目：`projects/shortlink-api/`
> 本课产出：`User` 表 + `POST /register`，密码以 bcrypt 哈希落库
> 新增：`auth.py`（加解密层）；`models.py` 加 `User / UserCreate / UserRead`
> 依赖：`uv add bcrypt pyjwt`

---

## 1. 为什么密码绝不能明文存

| 风险 | 说明 |
|---|---|
| 数据库泄露 = 密码泄露 | 明文库一丢，用户所有账号（很多人多站同密码）全暴露 |
| 内部人员能看到 | 运维、开发能直接读到别人的密码 |
| 无法辩解 | 日志、备份里可能已经到处都是 |

正确做法：**只存哈希**。校验时把用户提交的明文再算一遍哈希做比对 —— 存的是「不可逆的指纹」。

---

## 2. bcrypt：自带盐、不可逆、故意慢

```python
def hash_password(plain: str) -> str:
    return bcrypt.hashpw(plain.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(plain: str, hashed: str) -> bool:
    return bcrypt.checkpw(plain.encode("utf-8"), hashed.encode("utf-8"))
```

| 特性 | 意义 |
|---|---|
| 自带随机盐 | 同一个密码哈希两次结果**不同** → 彩虹表/撞库失效 |
| 不可逆 | 没法从哈希反推明文，只能正着再算一遍比对 |
| 故意慢 | 拖慢暴力破解速度（MD5/SHA1 太快，不能用于密码） |
| 长度上限 72 字节 | 超长会报错 → 模型里先 `max_length=72` 卡住 |

## 3. 三个模型分开：入库的、进来的、出去的

```python
class User(SQLModel, table=True):        # 数据库表：存哈希
    username: str = Field(index=True, unique=True)
    hashed_password: str

class UserCreate(SQLModel):              # 注册请求：收明文（落库前就被哈希掉）
    username: str = Field(min_length=3, max_length=32)
    password: str = Field(min_length=6, max_length=72)

class UserRead(SQLModel):                # 注册响应：只有安全字段
    id: Optional[int] = None
    username: str
    created_at: str
```

**`UserRead` 存在的唯一目的**：防止手滑把 `hashed_password` 返回给前端。
响应模型是最后一道闸 —— 就算有人改代码不小心把 User 整个返回，声明了 `response_model=UserRead` 也只输出这三个字段。

校验写在模型里（`min_length`），Pydantic 在入口拦住，路由里不用写 `if len(pw) < 6`。

## 4. 注册接口

```python
@app.post("/register", response_model=UserRead, status_code=status.HTTP_201_CREATED)
def register(req: UserCreate):
    try:
        return create_user(req)          # 内部：hash_password(req.password)
    except UserExistsError:
        raise HTTPException(409, "用户名已被注册")
```

明文密码的生命周期：请求体 → `create_user` → `hash_password` → **到此为止**，之后全程只传哈希。

| 状态码 | 触发 |
|---|---|
| 201 | 注册成功 |
| 409 | 用户名已被注册 |
| 422 | 用户名/密码长度不合规则（Pydantic 自动） |

---

## 5. 本机踩坑

| 现象 | 解法 |
|---|---|
| `bcrypt` 报密码过长 | 只处理前 72 字节；模型上 `max_length=72` 提前拦 |
| 库里加了 `owner` 列后报「no such column」 | `create_all` 不改老表结构（阶段 6 讲的迁移问题）；**开发期删掉 `shortlink.db` 重跑** |
| 循环导入（auth ↔ store） | auth 要查用户、store 要哈希密码 → 会互相 import。拆开：`auth.py` 只做加密不碰库，依赖放 `deps.py` |

## 6. 验证结果

```
POST /register alice                 → 201 {"id":1,"username":"alice","created_at":"..."}（无密码字段）
POST /register alice 重复             → 409 用户名已被注册
POST /register 密码 "123"            → 422 String should have at least 6 characters
sqlite 查 user 表                     → hashed_password = "$2b$12$m3ZBB..."（bcrypt 前缀）
明文 "secret123" 是否出现在哈希里      → False ✅
```
