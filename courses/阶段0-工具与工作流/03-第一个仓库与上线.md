# 阶段 0 · 第 3 课：第一个真实仓库（项目收口）

目标：把本地目录变成规范仓库，产出 README / PROJECT.md / .gitignore，并推送 GitHub。时长约 1.5 小时。

---

## 1. 仓库三件套

| 文件            | 给谁看          | 作用                                   |
| ------------- | ------------ | ------------------------------------ |
| `README.md`   | 别人（和未来的你）    | 这是什么、怎么跑起来、进度如何                      |
| `PROJECT.md`  | **给 AI 看**   | 技术栈、目录约定、命令约定、协作规则；每次提问前让 AI 先读它    |
| `.gitignore`  | 给 Git 看      | 哪些文件不入库（依赖、密钥、虚拟环境、临时文件）             |

**PROJECT.md 是这个学习路线的核心资产。** AI 每次会话都从零开始，没有它就每次都要重讲技术栈和约定。有了它，提示词只需一句「读 PROJECT.md，然后……」。

`.gitignore` 铁律：**密钥（`.env`）和依赖目录（`.venv`、`node_modules`）永远不入库**。密钥入库等于公开。

## 2. 已完成（本机实操）

```bash

git add -A                    # 全部入库
git commit -m "init: 建立学习仓库（README、PROJECT.md、课件）"
```

首次提交结果：commit `a30d22d`，12 个文件；`scratch/`、`.venv/`、`.workbuddy/` 已被 `.gitignore` 自动排除。

## 3. 本地 ↔ 远端

```
本地仓库  --git push-->   GitHub（origin）
         <--git pull--   协作改动、换机器恢复
```

| 命令                              | 作用                        |
| ------------------------------- | ------------------------- |
| `git remote add origin <url>`   | 绑定远端                      |
| `git push -u origin main`       | 首次推送，之后只需 `git push`      |
| `git pull`                      | 拉取远端更新（每天开工第一条命令）        |
| `git clone <url>`               | 把远端仓库下载到本地               |
| `git remote -v`                 | 看远端地址                     |

原则：**先 pull 再 push**；每天开工先 `git pull`，收工前 `git push`。

## 4. 三种认证方式

| 方式            | 命令                              | 评价                  |
| ------------- | ------------------------------- | ------------------- |
| **gh CLI（推荐）** | `gh auth login` → `gh repo create --public --source=. --push` | 一条命令完成登录+建库+推送 |
| SSH           | 生成密钥 → 公钥贴到 GitHub Settings → `push`   | 配一次长期免密      |
| HTTPS + Token | 每次输入 Personal Access Token      | 麻烦，token 会过期        |

## 5. 分支最小集（阶段 0 只了解）

| 命令                       | 作用             |
| ------------------------ | -------------- |
| `git branch`             | 看分支           |
| `git switch -c feat/xxx` | 新建并切到功能分支     |
| `git switch main`        | 切回主分支         |
| `git merge feat/xxx`     | 合并进来          |

规则：`main` 永远是可运行状态；改东西先开分支，跑通再合并。阶段 1 开始实战。
